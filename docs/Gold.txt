1. PROJECT OVERVIEW
-------------------

Project Name:
Olist Store SQL Data Warehouse

Database:
OlistStore_DW

Platform:
Microsoft SQL Server 2025 Express

Schema:
gold

Purpose:
The Gold Layer is the final analytical layer of the
data warehouse.

It transforms cleaned Silver data into a dimensional
data model optimized for business intelligence,
analytical queries and Power BI reporting.

The Gold Layer follows a Star Schema approach with
6 Dimension Tables and 4 Fact Tables.

4. GOLD FACT TABLES
-------------------

The Gold Layer contains 4 Fact Tables.


1. gold.fact_orders

   Grain:
   One row per order.

   Primary Key:
   order_id

   Foreign Keys:
   - customer_key
   - order_status_key
   - purchase_date_key
   - approved_date_key
   - delivered_carrier_date_key
   - delivered_customer_date_key
   - estimated_delivery_date_key

   Measures and Attributes:
   - order_count
   - approval_hours
   - delivery_days
   - estimated_delivery_days
   - delivery_delay_days
   - is_delivered
   - is_canceled

   Records: 99,441

   Purpose:
   Supports order volume, order status, delivery performance,
   cancellation and delivery delay analysis.


2. gold.fact_order_items

   Grain:
   One row per order item.

   Composite Primary Key:
   order_id + order_item_id

   Foreign Keys:
   - customer_key
   - product_key
   - seller_key
   - purchase_date_key
   - shipping_limit_date_key

   Measures and Attributes:
   - item_count
   - price
   - freight_value
   - item_total_value

   Records: 112,650

   Purpose:
   Supports product sales, seller performance, freight
   and item-level revenue analysis.


3. gold.fact_payments

   Grain:
   One row per payment transaction.

   Composite Primary Key:
   order_id + payment_sequential

   Foreign Keys:
   - customer_key
   - payment_type_key
   - purchase_date_key

   Measures and Attributes:
   - payment_count
   - payment_installments
   - payment_value

   Records: 103,886

   Purpose:
   Supports payment method, payment value and installment
   analysis.


4. gold.fact_reviews

   Grain:
   One row per review record.

   Composite Primary Key:
   review_id + order_id

   Foreign Keys:
   - customer_key
   - review_creation_date_key
   - review_answer_date_key

   Measures and Attributes:
   - review_count
   - review_score

   Records: 99,224

   Purpose:
   Supports customer feedback, review score and
   review trend analysis.


5. STAR SCHEMA RELATIONSHIPS
----------------------------

The Gold Layer follows a Star Schema design.

Dimension-to-Fact Relationships:

dim_customers:
- fact_orders
- fact_order_items
- fact_payments
- fact_reviews

dim_products:
- fact_order_items

dim_sellers:
- fact_order_items

dim_date:
- fact_orders
- fact_order_items
- fact_payments
- fact_reviews

dim_payment_type:
- fact_payments

dim_order_status:
- fact_orders

Total:
- 6 Dimension Tables
- 4 Fact Tables
- 19 Foreign Key Constraints

Note:
The Date Dimension is used in multiple roles, including
purchase date, approval date, delivery date, shipping date,
review creation date and review answer date.

The Customer Dimension is shared across all four
Fact Tables.


6. SURROGATE KEYS AND DATA MODELING
-----------------------------------

Surrogate Keys:

The following dimensions use surrogate primary keys:

- dim_customers: customer_key
- dim_products: product_key
- dim_sellers: seller_key
- dim_payment_type: payment_type_key
- dim_order_status: order_status_key

The Date Dimension uses date_key as its primary key
in YYYYMMDD format.

Business keys are retained in the dimension tables
for identification and traceability.

Fact tables use business identifiers and composite
keys according to their respective grain.


7. GOLD DATA LOADING PROCESS
----------------------------

The Gold Layer is populated from the Silver Layer.

Main processing steps:

1. Create the Gold schema and dimensional tables.
2. Load customer dimension records.
3. Load product dimension records.
4. Load seller dimension records.
5. Generate and populate the date dimension.
6. Load distinct payment types.
7. Load distinct order statuses.
8. Populate fact_orders.
9. Populate fact_order_items.
10. Populate fact_payments.
11. Populate fact_reviews.
12. Validate records, keys, relationships and measures.

All transformations and loading operations are performed
using SQL Server.
