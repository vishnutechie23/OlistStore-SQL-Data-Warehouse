1. PROJECT OVERVIEW
-------------------

Project Name:
Olist Store SQL Data Warehouse

Database:
OlistStore_DW

Platform:
Microsoft SQL Server 2025 Express

Schema:
silver

Purpose:
The Silver Layer is responsible for cleaning, standardizing
and validating the raw data received from the Bronze Layer.

It provides structured and reliable data for analytical
processing in the Gold Layer.

4. DATA CLEANING AND TRANSFORMATIONS
------------------------------------

The following transformations were performed using SQL Server.

A. Customer Data
   - Standardized customer information.
   - Checked customer IDs and unique customer IDs.
   - Validated NULL values and duplicate business keys.

B. Order Data
   - Standardized order status and timestamp columns.
   - Validated order IDs and customer relationships.
   - Investigated date sequence anomalies.

C. Product Data
   - Integrated English product category translations.
   - Preserved categories without available translations.
   - Validated product attributes and numeric values.

D. Seller Data
   - Standardized seller information.
   - Validated seller IDs and location attributes.

E. Order Item Data
   - Validated order and item identifiers.
   - Checked product and seller relationships.
   - Validated price and freight values.

F. Payment Data
   - Validated payment identifiers and payment types.
   - Checked payment values and installment values.
   - Validated order relationships.

G. Review Data
   - Cleaned whitespace-only review comments.
   - Converted whitespace-only comment values to NULL.
   - Preserved valid review comments and scores.
   - Validated review identifiers.

H. Geolocation Data
   - Investigated duplicate ZIP code and location combinations.
   - Removed duplicate geolocation combinations.
   - Final cleaned record count: 738,267.

I. Category Translation Data
   - Validated product category names.
   - Preserved translation records.
   - Checked category uniqueness.


5. DATA QUALITY VALIDATION
--------------------------

The following validation checks were performed:

1. Row Count Validation
   - Compared Bronze and Silver table record counts.
   - Verified expected records after transformations.
   - Geolocation record count reduced due to deduplication.

2. Duplicate Validation
   - Checked primary and composite business keys.
   - Validated uniqueness across Silver tables.

3. NULL Validation
   - Checked important business key columns.
   - Confirmed no unexpected NULL values in key columns.

4. Relationship Validation
   - Checked relationships between customers, orders,
     products, sellers, payments and reviews.
   - All 6 relationship checks returned zero unmatched records.

5. Numeric Validation
   - Checked negative and invalid numeric values.
   - No invalid values were found in the tested columns.

6. Date Validation
   - Investigated date sequence anomalies.
   - Preserved source data anomalies instead of
     automatically modifying business timestamps.


6. REVIEW COMMENT CLEANING
--------------------------

During review data validation, whitespace-only review
comments were identified.

A targeted UPDATE operation converted whitespace-only
comment values into NULL.

Final validation:

Total review records: 99,224
NULL review titles: 87,666
NULL review messages: 58,292
Silver vs Bronze comment mismatches: 0

Valid review comments were preserved.


7. PRODUCT CATEGORY TRANSLATION
--------------------------------

Product categories were integrated with the English
translation reference table using LEFT JOIN.

Translation coverage:

- 69 categories have English translations.
- 2 categories do not have English translations.

Categories without English translations:

1. portateis_cozinha_e_preparadores_de_alimentos
2. pc_gamer

These untranslated categories were preserved rather
than removed.


8. DATE QUALITY OBSERVATIONS
----------------------------

Some source order records contain date sequence anomalies.

Identified observations:

- 166 carrier timestamps occur before purchase timestamps.
- 23 customer delivery timestamps occur before carrier timestamps.
- 8 delivered orders have missing customer delivery timestamps.
- 75 canceled orders contain carrier timestamps.
- 6 canceled orders contain customer delivery timestamps.

These anomalies were inherited from the source dataset.

They were documented and preserved instead of applying
unverified corrections.
